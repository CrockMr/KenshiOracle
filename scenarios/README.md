# Original Kenshi scenarios

These JSON files describe experiments using [scenario format 0.1](../schema/scenario.schema.json). They contain no saves, game data or game assets. JSON validation establishes contract compliance; it establishes neither the existence of the save nor successful execution in Kenshi.

Keep source saves outside Git, available to the local installation used by the watchdog. Copy an example before adapting it and replace `save` with the exact name of that local copy, without a path. The runner reloads this save before each repetition and after the experiment; it cannot reconstruct an initially unsaved game.

For a scenario with orders, first load the save with `load_save(name="local-name")`, wait for a ready, paused world, then obtain a `dump_state()`. Copy the opaque identities actually exported into `character_id`, `squad_id` and `target_id` as required by the order. Verify that they identify the expected actors after reloading. Identities from a different save or mod set are not interchangeable. `move` requires a position `[x,y,z]`; `attack` requires a loaded target. Select exactly one character or one squad as the actor.

`at` is a number of **world-calendar seconds**, relative to the first paused state after loading. It is not a real-time waiting period, nor a number of simulated seconds: per MeitouClient's constant of `1200/11` simulated seconds per in-game hour, one simulated second is 33 calendar seconds, so the examples' checkpoints at 120 and 600 are about 3.6 and 18.2 simulated seconds. That conversion is **Verified** in MeitouClient's code but not yet measured on either target (**Unknown**); see [time units](../docs/protocol.md#time-units). At a shared time, actions execute in declaration order before the checkpoints; the report records the actual times reached and their overshoot. Reloading does not guarantee engine determinism.

Before calling `run_scenario(path="absolute-path-to-your-copy.json", repeat=3)`, load **the exact save named in this scenario's `save` field** with `load_save`, wait for a ready, paused world, then establish a known selection with `set_game_speed(speed=1, preserve_pause=True)`. Verify `get_scene_state().selected_game_speed == 1`; `get_clock().speed` remains zero while paused. This preparation is necessary after a manual load: the public SDK does not expose the previously selected speed. The runner captures the controls present when the call starts and finishes on the scenario's save; it does not automatically restore another initial save. A camera pose from another region may be clamped after reloading and fail restoration. Do not interact with the UI during the experiment.

Outputs are stored under `runs/<name>/<timestamp>/<execution>/`. `report.json` and `report.md` distinguish stable, variable and missing fields and record restoration. An error may leave `runtime/oracle-restoration.json` with `restore_required:true`; use `restore_scenario()` once a ready world is available, without deleting the journal to bypass verification. If the captured controls belong to another known save, `restore_scenario(save="known-original-copy")` can name it explicitly. It is recorded in `recovery_save`; the journal remains required until restoration is verified. See [first run](../docs/first-run.md) and [protocol](../docs/protocol.md).

Offline validation of the examples: `.venv/Scripts/python.exe -m pytest tests/test_oracle_examples.py -q`. This command does not launch Kenshi.
