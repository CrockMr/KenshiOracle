# KenshiProbe v0.11.0

Version 0.11.0 adds a scene-setup block to the native probe, the MeitouClient
adapter and the Python runner. After a reload and before checkpoint 0, a
scenario can spawn a squad, settle one simulated second, fully heal the
characters involved and set faction relations, then check each step by read-back.
The [scene-setup contract](../docs/scene-setup.md) defines names, keys, ranges
and refusal texts for both engines. Shared state stays at **0.2**; state 0.1
remains supported.

**Live validation is pending.** The setup block has not yet been run in the
original game or in MeitouClient. Fakes of both engines cover the commands,
the runner and the comparator; no real-game claim is made for this release.

Five new commands: `setup_info`, `setup_area_census`, `setup_spawn_squad`,
`setup_set_relation` and `setup_heal`. Mutations are accepted only after a
`load_save` with `allow_setup:true` (default false, echoed in the reply), in a
paused ready world with autosave disabled. Every mutating reply carries
`saved:false` and `world_mutated:true`; scene setup never saves.

`ping` adds `capabilities:["scene_setup"]`, `world_readiness`,
`world_mutated`, `build_commit` and `state_schema_version:"0.2"`. On both
engines, `build_commit` is the full commit the binary was built from, or
`"unknown"` for an uncommitted or unidentified tree.

`save_scene_snapshot` is refused while `world_mutated` is true, so a world
changed by scene setup cannot be saved; reload it first.
`prepare_town_scene` and `prepare_battle_scene` are unchanged, and
`issue_order` stays id-only.

Scenarios with a `setup` block use the separate format `scenario-0.2`
([schema](../schema/scenario-0.2.schema.json)). The 0.1 scenario format is
unchanged. The shipped [nature-bandit-ambush](../scenarios/nature-bandit-ambush.json)
scenario (save `oracle-base-nature`) spawns one bandit squad, sets relations to -60 both ways and orders the
attack at checkpoint 0 through runner-resolved aliases. Each execution writes a
receipt with every command sent, its reply and read-back, the dumps and the
`settings.cfg` squad-size line with its SHA-256.

Expected player positions come from a local **engine profile**, named by the
config key `engine_profile` and never committed
([schema](../schema/engine-profile.schema.json)). Pins exist only for
the save `oracle-base-nature`; any other save, missing entry or ambiguous match
fails closed before the first repetition.

`report.json` now carries `report_format`, `scenario_schema` and
`state_schema`, replacing the earlier `schema_version` key, together with
`build_commit`, `build_commit_known` and `limitations`. The runner accepts an
unknown commit with the limitation `commit unknown`; the comparator refuses
such a campaign. Reports from before 0.11 remain comparable for 0.1 scenarios,
with the limitation `build commit not recorded`.

For scenarios with a setup, the comparator classifies only the scene: aliases,
players and characters within `scene_radius`, intruders and the declared
relation pairs. Outcome metrics are reported per repetition. Background
metrics (population, clock, other relations) are recorded in
`report.background_metrics` but not compared. Scenarios without a setup are
compared as before.

The MeitouClient [patch series](../integrations/meitou/README.md) was
regenerated on upstream `88ae71a1` with **four patches**. Patch 4 sets
`OracleProtocol.AdapterVersion` to `0.11.0` and adds `build_commit`.
It is not an upstream release or an endorsement from the MeitouClient team.

Restoring captured controls that follow a character now commits only after the held
baseline shows the reference's settled follow pivot, without changing any tolerance.

The Python suite recorded **2,357 passed and 26 skipped**. These are unit and
fake-engine checks; they add no real-game loading claim.

Runtime environment of the earlier validations: **Kenshi 1.0.65 Steam,
RE_Kenshi 0.3.5, KenshiLib 0.5.0, Windows x64**. Native builds require Visual
C++ 2010 v100; Python tools require Python 3.11+. Other game/SDK combinations
are unverified.

The archive contains two project DLLs, the RE_Kenshi manifest, original empty
mod metadata, installation instructions and GPLv3. It contains no game files,
saved games, SDK binaries, private configuration, engine profiles or
decompiled executable code. The optional preload helper is inert without an
explicitly created activation file. **Raw PDBs are excluded** because they may
disclose source-machine paths. Check `SHA256SUMS` before installing.
