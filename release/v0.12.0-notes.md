# KenshiProbe v0.12.0

Version 0.12.0 adds three additive shared-state schemas to the native probe, the MeitouClient adapter and the Python runner. **State
0.5** is now the default dump schema; states 0.1 to 0.4 stay supported and their output is unchanged. The comparator also groups
divergent findings by root cause. The [scene-setup contract](../docs/scene-setup.md) of 0.11.0 is unchanged.

## What is new

- **State 0.3** ([coverage](../docs/state-coverage.md#extension-additive-03)): each character's `slave_state` and
  `slave_owner_faction_id`.
- **State 0.4** ([coverage](../docs/state-coverage.md#extension-additive-04)):
  - medical values (blood, bleed rate, hunger, fed, coma, blood-loss trauma), the treatment values of each body part and the 34
    stored stats;
  - `in_something` (bed, prison), `carrying` and `being_carried`, and each squad's `money`;
  - on MeitouClient, `order` from the character's task row.
- **State 0.5** ([coverage](../docs/state-coverage.md#extension-additive-05)):
  - each character's current AI `goal` (type, priority, target);
  - on MeitouClient, `order` from the carried plan step;
  - since patch 0009, the goal of a captive job its worker runs.
- **Native reads:** the native probe reads every new field by member reads only, with each offset checked at compile time against
  the public SDK headers.
- **Comparator** ([comparator](../docs/comparator.md)): divergent findings are qualified by exact permutation tests, grouped by
  root cause (one field repeated across squad groups is merged), and a draft issue is written per strong group.
- **Smaller additions:** the nearest-squad background metric and the relation-share wording of the scene reports.
- **MeitouClient [patch series](../integrations/meitou/README.md):** ten patches on upstream `88ae71a1`. New since 0.11.0:
  - 0005: calculated health maxima;
  - 0006, 0007 and 0008: states 0.3, 0.4 and 0.5;
  - 0009: captive job goals;
  - 0010: the adapter version 0.12.0.
- **[MeitouClient findings](../docs/meitou-findings.md):** each goal difference of the 0.5 live check, its MeitouClient cause and
  the upstream change that addresses it.

## Validation

- **Paused holds on both engines (Observed, N = 1 per engine and schema).**
  - The fields were checked on the owner's local saves: a slave-start hold for 0.3, and `oracle-base-cage-blesse` (caged and
    mining slaves, an injured caged prisoner) for 0.4 and 0.5.
  - Every 0.4 field with a save key equalled the saved value at load on both engines, except one native bandage 0.5 % lower.
  - In 0.5, goal types agreed in 778 of 1773 character checkpoint pairs where both were non-null. Priorities were equal in all 778.
  - The differences were MeitouClient's own defects, listed with their fixes in the findings.
  - These are field checks, not behaviour statistics. The interface checks of 0.4 and some fields stay **Unknown**; see the
    coverage pages.
- **Build and unit checks:** filled in when the reviewed DLL is built (Python suite, native suites, packaging).
- **The packaged DLL in game:** filled in after the exact-package installation test on the original.

## Compatibility

- **Same schema on both sides:** a campaign compares two engines only at the same state schema. Set the same `state_schema` in
  `config.json` and `config.meitou.json`. A Meitou build from a series before patch 0008 has no state 0.5
  ([MeitouClient target](../docs/meitou-target.md)).
- **Version check:** a probe or adapter older than 0.12.0 reports its own version through `ping`. The runner refuses a requested
  schema that the probe does not advertise.
- **Unchanged since 0.11.0:** the evidence and saves stay local; no game data is distributed. The installation layout is the same
  as in 0.11.0: upgrade by replacing the four files.
