# KenshiProbe v0.9.5

> Historical phase 1 notes. Do not publish this package against the current
> `main`; use the [v0.10.0 release](v0.10.0-notes.md).

KenshiProbe exposes the original Kenshi process as a local oracle: JSON requests
over TCP, canonical shared-state 0.1 snapshots, saved HAND identities, movement
and attack orders, and repeated scenarios with verified control restoration.
The Python MCP server and watchdog are available in the source repository.
The MeitouClient adapter and cross-engine statistical comparator are outside
this release.

Validated environment: **Kenshi 1.0.65 Steam, RE_Kenshi 0.3.5, KenshiLib 0.5.0,
Windows x64, Release / Visual C++ 2010 v100**. Python tools require Python 3.11+.
Other game versions, SDK combinations and Debug builds have not been validated.

The main archive contains our two DLLs, the RE_Kenshi manifest, a newly generated
zero-record mod descriptor, installation instructions and GPLv3. No game files,
saved games, SDK binaries or decompiled code are included. The optional preload
helper remains inactive without an explicitly created activation file.
PDB symbols are a separate optional archive. `SHA256SUMS` covers the DLLs and
archives; verify before installation.

Phase 1 validation records 1,602 passing Python tests and one Windows symlink
test skipped for missing privileges, synthetic canonicalization checks, three
example scenarios in the real game, and recovery/watchdog checks. The release
packaging check verifies extraction, manifest targets, the empty mod descriptor,
file hashes, installation over a synthetic existing mod and exact restoration.
Its result is an installation-layout check; runtime loading is a separate check.
The source documentation records the tested DLL versions and evidence scope.

Publication preparation adds a standalone scenario CLI requiring no MCP client
or AI agent. The current source suite passes 1,606 tests with one Windows symlink
skip. A fresh source clone passes 1,582 tests with 25 skips (24 optional historical
capture checks and the same symlink limitation). A real quiet-town CLI run
completed one repetition and three schema-valid, byte-verified snapshots with
verified control restoration. The packaged mod descriptor was loaded in that
run; the previous mod files, settings and four protected saves were preserved,
and the test process was stopped to restore the initial game-closed state.
Start from a loaded test game with stable camera controls; a cold menu load and
an animated camera were rejected in separate attempts. The supported
workflow starts from a loaded game and settled camera controls, as described
in `docs/first-run.md`.

Known limits: Kenshi is nondeterministic; identical input saves do not imply
identical populations or outcomes. Only proved saved HAND identities are stable.
Snapshots cover loaded objects and do not establish atomicity across every
engine worker. Unsupported task names remain unknown. Camera-follow restoration
supports loaded characters; other target types are refused. Recovery reloads the
scenario's source save and does not reconstruct unsaved play. Do not interact
with the game during a scenario. The listener is loopback-only, default port
47800, and the complete snapshot is written to a file rather than sent inline.
