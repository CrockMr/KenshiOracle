# KenshiProbe v0.13.0

Version 0.13.0 makes the oracle's answers easier to trust: an error keeps its code from the producer to the caller, a cancelled
tool still cleans up, and a public command measures how far two engines agree beside how far one engine agrees with itself. It
also corrects two rules of the native probe. The state schemas (0.1 to 0.5, 0.5 by default) and the
[scene-setup contract](../docs/scene-setup.md) are unchanged.

## What is new

- **Agreement between runs** ([agreement](../docs/agreement.md)): `launcher agree` and the MCP tool `agreement` compare the
  characters stored in a save between runs, field by field.
  - The original's agreement with itself is shown beside the candidate's agreement with the original.
  - Known artefacts are described in a rules file, as data, and counted apart.
- **Error codes from the producer to the caller** ([protocol](../docs/protocol.md)):
  - The native probe sends `world_not_ready`, `timeout`, `busy`, `not_implemented`, `internal_error` and `response_too_large` as
    their own code instead of `invalid_request` with a fixed message.
  - The client tells its own errors apart (`unreachable`, `no_reply`, `invalid_reply`) and marks `timeout` and `no_reply` as
    uncertain.
  - The runner and its reports carry the code.
- **Cleanup that survives a cancelled tool:** when an MCP client cancels a running tool, the runner still restores the scenario's
  controls, and the reference controller still stops the game it started and puts the player's RE_Kenshi profile and
  `settings.cfg` back.
- **Native probe, load rule** ([scene setup](../docs/scene-setup.md#gate)): a probe `load_save` is proved by the world itself
  (seen unavailable after the request, then ready).
  - Up to 0.12.0 the probe compared the game's current-game name, which no load changes.
  - A scene-setup scenario on the original failed at its first step unless the `continue=` line of `settings.cfg` named its save.
- **Native probe, main menu:** a command that needs the game loop is answered `world_not_ready` at once when no world is ready
  and no loop runs. Up to 0.12.0 it timed out after 9 s and held the queue meanwhile.
- **Large reports:** `compare` and `agree` read a report without its `variability` section. A five-repetition report (280 MB to
  1.7 GB) was refused for its size before.
- **MeitouClient [patch series](../integrations/meitou/README.md):** eleven patches on upstream `9a19748b` (.NET 11).
  - The series was rebuilt after upstream merged its `Engine` project into `Game` and enforced its naming rules.
  - Patch 0002 answers `busy`, like the native probe, to a `run_until` asked while another one runs.
  - Patch 0011 is the adapter version 0.13.0.

## Validation

- **Both engines in the game (Observed, one machine, 2026-11-12):**
  - A paused hold on a slave-camp save, five repetitions per engine: MeitouClient's goal types agree with the original's in
    94.6 % of the character pairs, the original's with its own in 94.1 %.
  - The same on a large-town save, for its 38 stored characters: 99.1 % and 98.3 %.
  - A scene-setup scenario, five repetitions per engine: the setup passed in all ten. Of 117 scene metrics one differs, the
    count of characters entering the scene at 330 s (0 on the original, 0 to 5 on MeitouClient).
  - A move order was carried out on both engines.
  - A scenario cancelled while it ran left a complete cleanup on both engines.
  - Seven error codes were seen as sent on both engines. `internal_error` and the `busy` of a full queue could only be produced
    with a private fault-injection build, which is not published.
- **The two probe corrections (Observed, original only, 2026-11-12, probe built from `2d6afcf`):**
  - At the main menu nine commands, then 20 in a row, were answered `world_not_ready` in under 20 ms.
  - With `continue=` naming another save, a load from the menu and a load from a ready world both completed, and a scene-setup
    scenario passed through the reference controller.
  - A failed load was not produced in the game; that it never completes is tested for the rule alone.
- **Build and unit checks (Verified):**
  - BUILD_PLACEHOLDER
- **The packaged DLL in game (Observed, one start):** GAME_PLACEHOLDER

## Compatibility

- **A 0.12.0 probe with this client:** the client recognises the fixed messages of the older probe and gives them the same codes.
  With that probe, commands at the main menu still time out, and a scene-setup scenario still needs `continue=` to name its save
  ([original reference](../docs/original-reference.md)).
- **MeitouClient:** a build from a series before this one answers `invalid_request` to a second `run_until`. Set the same
  `state_schema` on both sides, as before.
- **Not done:** recovery after MeitouClient crashes in the middle of a scenario, and anything on macOS.
- **Unchanged since 0.12.0:** the evidence and saves stay local; no game data is distributed. The installation layout is the
  same: upgrade by replacing the four files.
