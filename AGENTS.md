# Public documentation

- Write all public documentation in English, including README files, research notes, release notes, API/tool descriptions, CLI help and generated reports. Apply this rule to future additions and updates.
- Preserve API identifiers, filenames, save and scenario names, commands, JSON keys and original quoted runtime output. Literal data may retain its original language; translate the surrounding explanation.
- Use relative links for repository files and local evidence. Never include absolute paths from a contributor's machine.
- Preserve measurements, units, versions, hashes, evidence and uncertainty when translating. Distinguish **Verified**, **Observed** and **Unknown** claims; do not turn an observation into a general guarantee.
- Keep game files, saves, private configuration, raw captures and decompiled code out of Git. Public documentation may describe findings and link to ignored local evidence without copying those files.

The user's conversation language is independent of the documentation language.
